# @wren-cad/kernel

OCCT **8.0.1** compiled to WebAssembly with Wren's coarse C++ façade
([`src/whittle_kernel.h`](src/whittle_kernel.h), PLAN §7). Built with
[`@libcascade/toolchain`](https://www.npmjs.com/package/@libcascade/toolchain) 3.1.0
(opencascade.js v3, Emscripten 6.0.5) in digest-pinned Docker images (ADR-002).

JS can reach OCCT **only** through the façade. No OCCT class is registered with embind, so the
linker keeps only the OCCT code the façade references.

## Build

Requires Docker (or Podman) and about 21 GB of free disk for the two toolchain images (they share
layers: about 12 GB each alone, 21 GB together).

```sh
pnpm --filter @wren-cad/kernel build   # = pnpm kernel:build from the repo root
pnpm --filter @wren-cad/kernel test    # golden tests in Node, both variants
```

`pnpm build` runs [`scripts/build.mjs`](scripts/build.mjs):

1. `scripts/amalgamate.mjs` inlines `whittle_kernel.h`, `whittle_core.cpp`, `whittle_modeling.cpp`,
   `whittle_pushpull.cpp`, `whittle_shape_ops.cpp`, `whittle_copies.cpp`, `whittle_reference.cpp`,
   `whittle_measure.cpp`, `whittle_io.cpp`, `whittle_kernel.cpp` and `whittle_bindings.cpp` (in that
   order) into `.libcascade/whittle_facade.cpp`, and stamps
   `WHITTLE_BUILD_ID`.
   `WHITTLE_BUILD_ID` is a SHA-256 over the façade sources, `libcascade.config.ts`, the
   amalgamation script and the toolchain version, and `kernelInfo()` reports it. The amalgamation
   is needed because `customBindings` with `scope: 'main'` concatenates file _contents_ into the
   toolchain's embind translation unit, so relative `#include`s can't resolve there.
2. `libcascade build` links both variants in the pinned images. Each variant takes about 10 min
   with a warm image at M1 (2.5 min at M0); the OCCT objects are prebuilt in the image.
3. `libcascade assemble` generates the initialisers and the shared `types.d.ts`.
4. `scripts/size-report.mjs` prints raw, gzip and brotli sizes and writes `dist/size-report.json`.
   It fails if a kernel `.wasm` is larger than 15 MB brotli.

Don't run `npx libcascade build` on its own unless step 1 has already run: the config points at the
amalgamated file.

### Toolchain notes

- The `main`-scope TU is compiled twice. emcc compiles it for real. libclang 18 also parses it
  against parse-only embind stubs to extract the registration names, and any parse error aborts
  the build. The stubs lack `typed_memory_view`, so the views in `whittle_bindings.cpp` are guarded
  by `__wasm__`, which only the real compile defines. Avoid C++ that libclang 18 or its older
  libc++ can't parse (for example, floating-point `std::from_chars`).
- `assemble` (3.1.0) rejects the generated d.ts unless `FS` or `wasmMemory` is exported, so we
  export `wasmMemory`.
- OCCT 8 deprecates the `TopTools_*` collection typedefs. Use the `NCollection_*` templates.
- The image's `link` entrypoint runs the whole nx graph, and nx restores every cached step's
  outputs (generated bindings, docs) into the container's writable layer: several GB on the Docker
  disk. On a nearly full disk ("no space left on device" in the container log) point
  `LIBCASCADE_CONTAINER_CMD` at a wrapper that runs the same `link <yml>` through
  `--entrypoint /opencascade.js/build-wasm.sh` (the earlier steps' outputs are already in the
  image), with the yml path made absolute (`/src/…`) and `--tmpfs /tmp`. The M3.5 build used this.

## JS surface

[`src/facade.ts`](src/facade.ts) types the embind module. Every structured value is a JSON string
shaped like `packages/contracts/src/kernel.ts`, and every call returns a `Result` JSON. OCCT and
C++ exceptions are caught at each entry point and returned as `KernelError`s
(`OCCT_EXCEPTION`, `INVALID_INPUT`, `INVALID_HANDLE`, `UNRESOLVED_REFERENCE`,
`OPERATION_FAILED`, `UNSUPPORTED_FEATURE`, `INTERNAL`). The catch handlers cannot throw: on
`bad_alloc` a 256 KiB emergency reserve is released so the error JSON can still be built, and the
last resort is an empty string (the worker reports it as a malformed result).

| Call                                       | Returns                                                         |
| ------------------------------------------ | --------------------------------------------------------------- |
| `execFeature(feature, inputs)`             | `FeatureResult` (+ `frame`, `regions`, `bodies` where relevant) |
| `mesh(shape, options, out)`                | `{}`; buffers in `MeshData`                                     |
| `massProperties(shape, densityKgPerMm3)`   | `MassProperties`; `mass` + `inertia` when density > 0           |
| `fingerprints(shape)`                      | `ShapeFingerprints` (TopExp order)                              |
| `exportShapes(shapes, format, options)`    | `{path, files:[{path,name}]}` in MEMFS (`step`, `stl`, `brep`)  |
| `importFile(path, format)`                 | `{bodies:[{shape,name?}]}` (`step`, `iges`, `brep`, `stl`)      |
| `measure(query)`                           | `Measurement` (M2; `{a, b?}`, see below)                        |
| `projectEdges(query)`                      | M3: `ProjectedEdge[]` (`{shape, edges, plane, exact?}`, below)  |
| `projectFaceOutline(query)`                | M3: `{outer, inner}` (`{shape, face, plane, exact?}`)           |
| `configureThreads(count)`                  | `{threads, max}` (threaded build; no-op single)                 |
| `release(shape)`, `liveHandleCount()`      |                                                                 |

The module also exports Emscripten's `FS`; the worker reads exported files with `FS.readFile` and
unlinks them, and writes imported bytes with `FS.writeFile`.

### Features (M1)

The kernel never resolves persistent names: the regen engine passes sub-shapes as
`inputs.refs[<JSON pointer>] = {shape, kind, index}` and values in mm/rad keyed by JSON pointer.

| Feature     | Inputs                                                                                                                       |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `primitive` | `box` (`/dx /dy /dz`), `cylinder` (`/radius /height`, axis = frame Z), `sphere` (`/radius`); op ≠ new acts on `inputs.target` |
| `sketch`    | `frames.plane` (default world XY); solved `entities`                                                                         |
| `extrude`   | refs `/profile/<n>` (region faces); `/end/depth`; up-to: refs `/end/target` (planar face) or `frames.upTo`; `/draft` must be 0 |
| `revolve`   | refs `/profile/<n>`; axis: refs `/axis` (straight edge) or `frames.axis` (origin + z); `/angle`                              |
| `fillet`    | refs `/edges/<n>` on `inputs.target`; `/radius`                                                                              |
| `chamfer`   | refs `/edges/<n>`; `/mode/distance` (+ `/mode/angle`)                                                                        |
| `boolean`   | `inputs.target` or refs `/target`; refs `/tools/<n>` (or `shapes["tools…"]`)                                                 |
| `plane`     | `definition.frame`, or offset `/definition/distance` from refs `/definition/from` or `frames.from`                           |
| `pushPull`  | M2: `inputs.target` (else the first face's shape); refs `/faces/<n>` (planar faces of it); `/distance` mm along each outward normal |

Body ops `add | cut | intersect` act on `inputs.target` plus `inputs.shapes["scope…"]` (key
order). `add` fuses all of them into one result; `cut`/`intersect` return the target's result as
`shape` and the others in `bodies: [{key, shape, naming}]`.

**Sketch regions** are the bounded faces of the planar arrangement of all non-construction
curves (minimal regions, as in Onshape/Fusion): the curves are split at their intersections with
the General Fuse algorithm (`BRepAlgoAPI_BuilderAlgo`, fuzzy 1e-6 mm, which also merges coincident
end points of different entities), then every piece goes in both orientations to
`BOPAlgo_BuilderFace` on the sketch plane, the recipe of `BOPAlgo_Tools::WiresToFaces`. A loop
inside another becomes that face's hole and is also a region itself; open and dangling curves
bound nothing and are dropped. A rectangle with a circle in it therefore gives
`S…:region(L1,L2,L3,L4|C1)` (the plate) and `S…:region(C1)` (the disc).

**Push/pull** (M2, ADR-013): each face is copied and swept by `d · n` (`BRepPrimAPI_MakePrism`),
then one boolean with all prisms: fuse for d > 0, cut for d < 0. Seams the operation creates
between faces on one surface are merged with `ShapeUpgrade_UnifySameDomain`:
- old face + wall: pulling a box top gives a taller 6-face box, not a seam line;
- old face + moved face: a pocket floor pulled flush closes the pocket;
- wall + wall, and pieces of one split face.

All other edges and vertices are kept. Then `BRepCheck_Analyzer` runs, with `ShapeFix_Shape` only
when the result is invalid; an invalid result is an error, never returned. Errors:
- a curved face → `UNSUPPORTED_FEATURE` ("Selected face 2 is curved (cylinder) …", the face as
  `entityRefs`, `detail` = pointer and body face index);
- a push that removes everything → `OPERATION_FAILED` "… removes the whole body";
- an edge or a face of another body → `INVALID_INPUT`;
- zero distance → `INVALID_INPUT`.

A push that splits the body warns.

**Measure** (M2): `measure('{"a": T, "b"?: T}')`, where `T` is a `ResolvedRef`
(`{shape, kind: face|edge|vertex|body, index}`) or `{point: [x, y, z]}`.
- One target gives:
  - vertex or point: `position`;
  - edge: `length`, plus `radius` for circles;
  - face: `area`, plus `radius` for cylinders and spheres;
  - body: `area`.
- Two targets give `distance` (`value` plus the closest points `a` and `b`, from
  `BRepExtrema_DistShapeShape`; with several solutions, the one nearest the centre of `a`), and an
  `angle` in rad:
  - face–face: between the outward normals, [0, π];
  - edge–edge: the corner angle when the edges share a vertex, otherwise the angle between the
    lines, [0, π/2];
  - face–edge: between the line and the plane.

### Features (M3)

Inputs follow the rule above: refs and values are keyed by JSON pointer into the feature, frames
by pointer too (origin planes/axes/points and reference features resolve to frames), with the
role keys of `kernel.ts` (`plane`, `axis`, `upTo`, …) accepted as well.

| Feature                    | Inputs                                                                                                                                                         |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `shell`                    | `inputs.target` (else the first face's body, or refs `/body`); refs `/openFaces/<n>`; `/thickness`; `direction` inward / outward. No open faces = hollow solid |
| `draft`                    | `inputs.target`; refs `/faces/<n>`; neutral plane at refs `/neutral` (planar face) or `frames["/neutral"]` / `frames.neutral`; `/angle` rad; `reverse`                             |
| `sweep`                    | refs `/profile/<n>` (or every region of `shapes.profile`); refs `/path/<n>` edges in chain order; `orientation`; op/scope as extrude                           |
| `loft`                     | refs `/sections/<n>`: region faces, closed edges, or vertices (first/last only); `ruled`, `closed`; op/scope as extrude. `guides` give a warning (ignored)      |
| `mirror`                   | plane at refs `/plane` or `frames["/plane"]` / `frames.plane`                                                                                                   |
| `linearPattern`            | direction at refs `/direction` (straight edge, circular edge or cylinder axis, planar face normal) or `frames["/direction"]` / `frames.direction` / `frames.axis` (z); second direction also `frames.second`; `/count`, `/spacing`; `second`: `/second/direction`, `/second/count`, `/second/spacing` |
| `circularPattern`          | axis at refs `/axis` or `frames["/axis"]` / `frames.axis`; `/count`, `/angle`; `equalSpacing`                                                                   |
| `hole`                     | `inputs.target`; `frames["hole:<i>"]` (origin on the face, z into the material); values below; `end` blind / throughAll / upTo (refs or frames `/end/target`, or `frames.upTo`) |
| `import`                   | `inputs.shapes["source…"]`: raw handles from `importFile` (key order); `frame`; `op`/scope                                                                    |
| `thread`                   | refs `/face` (cylindrical); returns the body unchanged plus the cylinder `frame` and `radius`                                                                  |
| `axis` / `point` / `plane` | refs or frames at the definition's pointers (`/definition/a`, `/definition/face`, …); values `/definition/<field>`; the result carries `frame`                  |

**Copies** (mirror and both patterns). Feature copies: each source feature's tool solid is
`shapes["tool:<featureId>"]` with its op in `values["/ops/<featureId>"]` (0 add, 1 cut;
2 intersect is refused with `UNSUPPORTED_FEATURE`), applied to `inputs.target` in source order,
all instances of one feature in **one** `BRepAlgoAPI` boolean with a multi-tool argument (no
inverted-solid check; parallel in the threaded build). Rigid instances are moved shapes (shared
geometry); mirrors are rebuilt (`BRepBuilderAPI_Transform`). A feature's tool solid is what it
returns with `op: "new"`; a `hole` without `inputs.target` (or with an extra `"op": "new"`)
returns its drill solids as one shape (through-all tools are sized by the target when given, else
10 m deep). Body copies: refs `/source/bodies/<i>`; `merge` fuses the originals and every copy
into one body (one boolean), otherwise the copies come back as separate bodies: `bodies` lists
every copy (the first is also `shape`) with keys `inst<k>:<i>` (`mirror:<i>`), body `i` outer,
instance inner.
Instances: linear `k = row · count + column` (row along `second`); circular `k = 1…count−1` at
`k · step`, where `step = angle / count` for a full 360° with `equalSpacing`, `angle / (count − 1)`
for a partial span with `equalSpacing`, and `angle` itself otherwise. `skip` removes indices
without renumbering the rest. Instance 0 is the original.

**Hole values** (the regen engine resolves the tables; pointers are the feature's own fields, set
even when the field is absent): `/diameter` (clearance or tap drill), `/end/depth` (blind: face to
the end of the full-diameter wall; the drill point adds `r / tan(tip/2)`), `/tipAngle` (blind
only; absent = flat bottom), `/counterbore/diameter` + `/counterbore/depth`,
`/countersink/diameter` + `/countersink/angle` (included angle). Tapped holes use the drill
diameter; the thread is cosmetic. Each hole is a revolved profile that starts `max(1, 2r)` above
the face so the cut leaves no coincident skin; all holes go in one multi-tool cut.

**Reference geometry.** `axis` returns a segment named `F…:axis` with `frame` (origin + z):
`twoPoints`; `edge` (straight); `cylinder` (cylindrical/conical face or circular edge, spanning
its extent); `twoPlanes` (origin = the line point nearest the planes' own origins);
`pointNormal`. `point` returns a vertex `F…:point` with `frame.origin`: `coordinates`
(`/definition/x|y|z`), `vertex`, `center` (circular edge, sphere), `alongEdge` (`/definition/t`
as a fraction of the arc length, in the curve's parameter direction), `intersection` (edge × face
or plane, edge × edge; frames read as the EntityRef kind: face = plane, edge = axis). `plane` adds
`threePoints` (origin = the first, x towards the second), `angle` (through the axis, rotated
`angle` from `from` about it), `normalToCurve` (`at` a vertex, or `/definition/at/t`),
`midplane`, `throughPoint`, and `flip` for every kind.

**Draft direction.** The pull direction is the neutral plane's normal (a face's outward normal)
and the body narrows along it; `reverse` flips both. With the bottom face of a box as the neutral
plane, a positive angle leans a side face out at the top.

**Shell.** `BRepOffset_MakeOffset` (thick solid with the open faces as closing faces; with none,
an offset solid that becomes the void of a hollow solid), sharp intersection joins; if OCCT cannot
build those (some curved bodies) it retries with rounded arc joins and warns. A result that is
invalid, self-intersecting or not smaller than the body (inward) is `OPERATION_FAILED`
"The shell is too thick for this body" with the open faces as `entityRefs`.

**Sweep** uses `BRepOffsetAPI_MakePipeShell` per profile wire (outer minus holes):
`followPath` = corrected Frenet, `fixed` = constant trihedron (the profile translates). The profile
stays where it is (no contact/correction). A result that `BOPAlgo_CheckerSI` finds
self-intersecting is `OPERATION_FAILED`.

**Loft** uses `BRepOffsetAPI_ThruSections` (solid, compatibility check on). Sections with holes
are `UNSUPPORTED_FEATURE`. Guides are infeasible with ThruSections (it has no guide input; the
alternatives, `MakePipeShell` with an auxiliary spine or `BRepFill_Filling` patches, change the
result class), so they are ignored with an `UNSUPPORTED_FEATURE` warning.

**Fillet/chamfer `propagate: false`.** OCCT cannot stop a blend at a tangent edge: every
`BRepFilletAPI_MakeFillet::Add` / `BRepFilletAPI_MakeChamfer::Add` calls
`ChFi3d_Builder::PerformElement` (`ChFi3d_Builder_1.cxx`, called from `ChFi3d_FilBuilder.cxx` and
`ChFi3d_ChBuilder.cxx`), which always walks on along tangent-continuous edges; there is no flag.
So with `propagate: false` the façade compares the contour OCCT built (`NbContours`/`NbEdges`/
`Edge`) with the selection: equal → a normal blend; longer → `UNSUPPORTED_FEATURE` "The fillet
cannot stop at tangent edges", with the selected and the extra edges as `entityRefs`. It never
blends more than was selected without saying so. Golden: one straight top edge of a slot pulls in
both arcs and the other line.

**Projection** (`projectEdges`, `projectFaceOutline`, for "convert entities"). Coordinates are the
plane frame's local x/y. Lines stay lines; circles and arcs whose axis is parallel to the plane
normal stay `circle`s and counter-clockwise `arc`s (from either side of the plane); everything else
(circles seen obliquely, ellipses, B-splines) is a `polyline` sampled with
`GCPnts_TangentialDeflection` (0.05 rad, 1 µm) and projected; a sampled curve that projects onto a
line (a circle seen edge-on) is one `line`. Edges along the normal project to points and come back
with no curves. Outlines list the outer loop, then each inner loop, in wire order.

With `exact: true` in the query (M3.5, `ExactProjectedEdge`), the projection is exact for conics
and B-splines in any orientation, because projecting along the normal is affine: circles seen
obliquely and ellipses are `ellipse` / counter-clockwise `ellipticArc` (`c`, `majorRadius`,
`minorRadius`, `rotation` in (−π/2, π/2], `start`, `end`), still `circle` / `arc` when the result
is circular; B-spline and Bezier edges are `bspline` (`poles` projected, the curve's own `degree`,
`weights` when rational, OCCT `knots` + `multiplicities`; trimmed edges are segmented and clamped,
a whole periodic curve stays `periodic`). These map one-to-one onto `SketchEllipse`,
`SketchEllipticArc` and `SketchBSpline`. Edge-on projections and other curves are sampled as
above. Without the flag the output is the M3 one.

**IGES** (`importFile(path, "iges")`): `IGESControl_Reader`; solids are kept, loose faces are sewn
(`BRepBuilderAPI_Sewing`, 1 µm tolerance) and closed shells become solids, open shells stay
shell bodies. Lengths arrive in mm. A `WREN_NO_IGES=1` build leaves the reader out (size
measurements); it answers `UNSUPPORTED_FEATURE`.

**Import feature.** Replaces the M1 TypeScript workarounds (BREP location rewriting and a no-op
intersect for naming): the raw shapes are moved by the feature's `frame` (shared geometry, no
round trip) and named in C++: faces `F<id>:face#k` per body by geometric key, edges and vertices
from their faces, bodies ordered by the geometric key of their volume centroid (`shape` first,
then `bodies` keyed `body#<k>`); add/cut/intersect name tool faces `F<id>:face(F<id>:face#k)`; a
mesh reference body (STL) is one face `F<id>:face` and only `op: "new"`.

**Performance** (PLAN §10, 300 ms regen budget): a 10 × 10 pattern of Ø5 through holes on a
200 × 200 × 10 plate, as a pattern of a hole feature, is one 99-tool cut. The golden gates the
smaller of each run's wall and process CPU time (wall inflates on oversubscribed CI machines,
CPU while V8 tiers up the module on background threads), best of five warm runs.

### Sketch curves (M3.5)

`ellipticArc` and `bspline` entities become exact edges (ADR-pending "M3.5 kernel"):

- **Elliptic arc**: `gp_Elips` (major axis at `rotation`; `minorRadius > majorRadius` swaps the
  axes, like `ellipse`) trimmed by `GC_MakeArcOfEllipse`, counter-clockwise from `start` to `end`.
  The end points must lie on the ellipse within 1e-6 · max(1, a) mm.
- **B-spline**: `Geom_BSplineCurve` from the pole points, `weights`, `knots` + `multiplicities`
  (OCCT form: distinct knots, both or neither; an open spline may give a flat vector of
  n + degree + 1 knots instead, ADR-048), `degree`, `periodic`. Defaults: clamped =
  multiplicity degree + 1 at the ends and interior knots `i / (n − degree)`; periodic = `n + 1` knots
  `i / n`, multiplicity 1. Non-periodic splines must be clamped; their end poles are the shared
  vertices of the lines and arcs that end there. A closed clamped spline (last pole = first) or a
  periodic one bounds a region on its own.
- Bad input is `INVALID_INPUT` with `entityRefs: ["S…:e(<id>)"]`: degree (integer 1 … 25), too
  few poles (degree + 1), weights (> 0, one per pole), knot vector length, ordering, clamping,
  multiplicities, zero size; elliptic arcs off their ellipse, without sweep or with bad radii.
- Edges keep `S…:e(<id>)`; fingerprints report `bspline` / `ellipse`; side faces are `extrusion` /
  `revolution` surfaces named `F…:side(S…:e(<id>))`. Fillets on spline-to-line and spline-to-cap
  edges work.

**Mass properties of spline profiles.** BRepGProp's default Gauss rule does not split at knots,
so piecewise B-spline profiles were 1e-5 to 3e-3 off. `massProperties` and `measure` convert shapes
with a planar face bounded by a free-form edge, or an extrusion/revolution of a free-form curve, to
NURBS and integrate adaptively (relative 1e-12, better than 1e-9 achieved; about 3× the default's time on
those shapes only). Fingerprint areas and naming centroids keep the default; fingerprint lengths of
free-form edges use `GCPnts_AbscissaPoint` (1e-10).

### Naming (packages/contracts/src/naming.ts)

- Sketch: `S<id>:e(<entity>)` (split curves `…#k`), `S<id>:p(<point>)` (coincident points are
  extra naming entries on the same vertex), `S<id>:region(…)`.
- Extrude/revolve: `F<id>:start`, `F<id>:end` (from `FirstShape`/`LastShape`; revolve only below
  360°) and `F<id>:side(<profile edge name>)` (`Generated`).
- Booleans, fillets and chamfers carry face names through `Modified`/`IsDeleted`. Target faces
  win over tool faces. New faces are `F<id>:fillet(<edge>)`, `F<id>:chamfer(<edge>)` (also
  `(<vertex>)` for corner blends) and, in a `boolean` feature, `F<id>:face(<tool face>)`. Tool
  faces of extrude/revolve/primitive body ops keep the tool's own names.
- Edges `edge(<A>|<B>)` and vertices `vertex(<A>|<B>|<C>)` come from the sorted adjacent face
  names; seams read `edge(A|A)`, free edges `edge(A)`. Primitives keep their local form,
  `F<id>:edge(face.xmin|face.ymin)`.
- Splits: when several faces inherit one name, every face sharing that base name is re-indexed
  `#0…` by centroid (x, then y, then z, rounded to 1e-6 mm). So names keep a single `#k`
  level, and names that survive one-to-one stay as they are.
- Cylinder: `face.side`, `face.zmin`, `face.zmax`. Sphere: `face.sphere`; its pole edges are
  `edge(face.sphere)#0/#1`.
- Push/pull: moved faces keep their names; walls are `F<id>:side(<boundary edge name>)`; when
  faces merge, old > moved > wall (a wall merged into a side face takes its name; a moved face
  flush with an old face disappears).
- Faces no rule names (not expected) get `F<id>:unnamed#k`.
- M3: shell offset faces `F<id>:shell(<face>)`, rims `F<id>:rim(<open face>)` (OCCT builds one
  annular rim face per open face, the closing face's `Modified` image); drafted faces keep their
  names (`ModifiedShape`); sweep/loft `F<id>:start`, `F<id>:end`, `F<id>:side(<profile curve>)`;
  copies `F<id>:inst<k>(<N>)` / `F<id>:mirror(<N>)`; holes `F<id>:hole(<point name>):wall`,
  `:bottom`, `:tip`, `:cbore.wall`, `:cbore.floor`, `:csink` (the point name is the feature's
  `points[i].name`, `#<i>` when absent); reference geometry `F<id>:axis` (edge), `F<id>:point`
  (vertex), `F<id>:plane` (face).

### Mesh caching

Triangulations live in the shared TShapes, and `BRepMesh_IncrementalMesh` keeps any existing mesh
that is fine enough. `mesh()` drops the cached triangulation (`BRepTools::Clean`) when its recorded
edge deflection is under half the requested one, so a coarser request after a finer one is
honoured. `relative` deflections are converted with the shape's largest bbox extent. STL export
meshes a copy (`BRepBuilderAPI_Copy`), so export quality never changes the viewport mesh.

### Data exchange

- **STEP**: through an XCAF document (`STEPCAFControl_Writer`/`Reader`), so product names and
  colours round-trip. OCCT 8 sets the schema with `DESTEP_Parameters::WriteSchema` passed to
  `Transfer(doc, params, …)`. `Interface_Static` `write.step.schema` still exists but is not
  needed: AP214 → `AP214IS`, AP203 → `AP203`, AP242 → `AP242DIS`. Units are mm. On import,
  assemblies are flattened with their placements, one body per solid.
- **STL**: our own writer (binary or ASCII; merged or one file per body) from a `BRepMesh`
  triangulation at the requested deflection. The output is watertight because BRepMesh is
  conformal across shared edges. Import uses `RWStl::ReadFile` into one triangulation-only face.
- **BREP**: `BRepTools::Write`/`Read` (exact).
- **IGES** (M3, import only): see Features (M3).
