# Part and assembly configurations in CAD tools (for Wren PLAN M3.7)

Scope: how SolidWorks, Onshape, Autodesk Fusion, Creo, NX and FreeCAD model part and assembly configurations; what users complain about and praise; how configurations interact with drawings, BOMs and exports; and recommended defaults for Wren. Research date: 2026-11-10. Many SolidWorks help pages are version-stamped (2012–2024). A page older than 2020 is marked **[historical]** but is still cited, because the behaviour is long-standing and the 2020+ pages repeat it.

Source quality key: **[vendor]** = official help or blog; **[VAR]** = reseller or partner blog; **[user]** = forum, Reddit or review site (opinion or anecdote, not verified).

## 1. How each tool models configurations

### Takeaway
There are two families of design. **Table-of-variants** tools (SolidWorks, Creo family tables, NX part families, FreeCAD configuration tables) store one row per named variant, with columns for dimensions and suppression. **Input-driven** tools (Onshape, and to some extent Fusion) define typed *inputs* (list, checkbox, bounded variable), and the variant is the combination of those inputs. Every tool has two things in common: a default or generic that the variants override, and a clear split between configured values (per variant) and unconfigured values (shared by all variants).

### Cited Findings

**SolidWorks**
- When a dimension changes, the user picks a scope: *This configuration*, *All configurations* or *Specify configurations*. "Specify" applies the change to the active configuration plus any others the user selects. The scope is set from the Configurations button in the Dimension PropertyManager. [vendor] — [SW Help 2022: Apply to configs](https://help.solidworks.com/2022/English/SolidWorks/sldworks/HIDD_APPLY_TO_CONFIGS.htm); [SW Help 2016: changing dimensions by configuration](https://help.solidworks.com/2016/english/SolidWorks/sldworks/t_changing_dimensions_by_configuration.htm) [historical]
- **Derived configurations** are children of a parent configuration. By default, every parameter in a child is linked to its parent, and the user can override any configurable parameter so that it stops following the parent. A "Link to parent configuration" option appears only for derived configurations. [vendor] — [SW Help 2012: Derived Configurations](https://help.solidworks.com/2012/English/SolidWorks/Sldworks/Derived_Configurations.htm) [historical]; [SW Help 2015: specify configurations](https://help.solidworks.com/2015/ENGLISH/SolidWorks/sldworks/t_specify_configurations.htm) [historical]; [Javelin: Derived configurations](https://www.javelin-tech.com/blog/2018/08/solidworks-derived-configuration/) [VAR, historical]
- In SolidWorks' own example, editing a parent's extrude with *This Configuration* selected changes the parent and its derived child but leaves an unrelated top-level configuration unchanged. In other words, "this configuration" in practice means "this configuration and its descendants". [vendor] — [SW Help 2012: Example of Derived Configurations](https://help.solidworks.com/2012/English/SolidWorks/Sldworks/Example_of_Derived_Configurations.htm) [historical]
- The **Modify Configurations** dialog is a grid of configurations against configured parameters. A value highlighted in yellow is a derived configuration that overrides its parent. [vendor] — [SW Help 2020: Modify Configurations dialog](https://help.solidworks.com/2020/English/SolidWorks/sldworks/r_modify_configurations_dialog.htm)
- **Design tables** are embedded Excel worksheets with one row per configuration and one column per parameter. Special columns such as `$PARTNUMBER` set the BOM part number for each configuration. [vendor] — [SW Help 2022: Component Part Number in Configurations](https://help.solidworks.com/2022/english/SolidWorks/sldworks/r_Component_Part_Number.htm)
- **Configuration properties** include BOM options. "Part number displayed when used in a bill of materials" can be *Document Name*, *Configuration Name*, *Link to Parent Configuration* (derived configurations only) or *User Specified Name*. A document-level default for new configurations is set in Tools > Options > Document Properties > Configurations. [vendor] — [SW Help 2024: Configuration Properties PropertyManager](https://help.solidworks.com/2024/English/SolidWorks/Sldworks/HIDD_NEW_ADD_CONFIG.htm); [SW Help 2023: Document Properties – Configurations](https://help.solidworks.com/2023/English/SolidWorks/Sldworks/HIDD_OPTIONS_CONFIGURATIONS.htm)
- The configuration properties also include an option that suppresses new features and mates in *other* configurations when they are added. A reseller warns that this option makes mates "disappear" when the user switches configuration. [VAR] — [CATI: SOLIDWORKS Configuration Advanced Options](https://www.cati.com/?p=119967)
- **Configuration Publisher** builds a custom PropertyManager, which lets someone pick a configuration by its parameters when they insert the part into an assembly or download it from 3D ContentCentral. It exists because "finding the correct configuration can be difficult if the list is long or the configuration names are not descriptive enough". It requires a design table, even when the model has only one configuration. [vendor] — [SW Help 2020: Configuration Publisher](https://help.solidworks.com/2020/English/solidworks/sldworks/c_configuration_publisher_top.htm); [SW Help 2020: Specifying Multiple Configurations Using Configuration Publisher](https://help.solidworks.com/2020/english/ccsupplier/c_ssh_spec_mult_configs.html)

**Onshape**
- Onshape has three input types. A **List** is a table of named rows, and the first row is Default. A **Checkbox** toggles features on or off, appears as a checkbox in the Insert dialog, and can drive several parameter columns. A **Configuration variable** is referenced as `#name`, has a type (Length, Angle, Integer, Real or Text) and has Default, Minimum and Maximum values. [vendor] — [Onshape Help: Part Studio and Assembly configurations](https://cad.onshape.com/help/Content/PartStudio/part_studio_and_assembly_configurations.htm)
- Each Part Studio, Assembly or Variable Studio has one Configurations panel, which can hold many inputs, each shown as a collapsible table. [vendor] — [Onshape Help: Configurations](https://cad.onshape.com/help/Content/configurations.htm)
- **Configure mode** puts a yellow banner across the workspace. Configurable fields highlight in yellow on hover. Clicking a field adds a column, named "feature name + parameter name", and gives the field a dashed yellow outline. A parameter already used by another input is outlined and can't be configured twice. Suppression can be configured by right-clicking the feature and choosing *Configure suppression*. Double-clicking a table cell reopens the feature dialog with that parameter highlighted in blue. Tolerances can be set per cell. [vendor] — [Onshape Help: Part Studio and Assembly configurations](https://cad.onshape.com/help/Content/PartStudio/part_studio_and_assembly_configurations.htm)
- In a Part Studio, the configurable items include feature values, suppression, custom FeatureScript features, **part numbers, colours and materials**. In an assembly, mates, instances and patterns can be configured, but mate connectors can't. [vendor] — same page
- Configuration tables accept spreadsheet paste. Extra pasted rows are created automatically, but extra columns are not. Configuration inputs can be copied between Part Studios, assemblies and Variable Studios, and between documents. [vendor] — [Onshape Help: Configurations](https://cad.onshape.com/help/Content/configurations.htm)
- Configurations can only be created or edited in the browser. iOS and Android can view the panel and switch configurations. [vendor] — [Onshape Help: Part Studio and Assembly configurations](https://cad.onshape.com/help/Content/PartStudio/part_studio_and_assembly_configurations.htm)
- **Variable Studios** can also be configured. [vendor] — [Onshape Help: Variable Studio configurations](https://cad.onshape.com/help/Content/VariableStudio/variable_studio_configurations.htm)

**Autodesk Fusion**
- Configurations shipped in the **September 2023** update. [vendor] — [Fusion blog: September 2023 Product Update](https://autodesk.com/products/fusion-360/blog/september-2023-product-update-whats-new)
- An Autodesk forum moderator said Configurations needs a commercial subscription or an educational licence, plus a Team hub; it is not available on a Personal hub. An Autodesk pricing post points personal users to the commercial subscription for "recently added configurations". [user/vendor forum, 2023] — [Autodesk forum: new configurations feature missing](https://forums.autodesk.com/t5/fusion-support/new-configurations-feature-missing/m-p/12322886); [Fusion blog post 61755](https://www.autodesk.com/products/fusion-360/blog/?p=61755)
- A **Configured Design** defines two or more configurations in a **Configuration Table**, where rows are configurations and columns are configured aspects. The configurable aspects are User Parameters, Feature Parameters, Suppression, Visibility, Physical Material, Appearance, Sheet Metal Rules, Plastic Rules and Properties. [vendor] — [Fusion Help: Configurations overview](https://help.autodesk.com/cloudhelp/ENU/Fusion-Configurations/files/CFG-OVERVIEW.htm); [Fusion Help: Configuration Table](https://help.autodesk.com/cloudhelp/ENU/Fusion-Configurations/files/CFG-CONFIGURATIONS.htm)
- **Theme tables** are child tables below the top table. They group related aspects (material, appearance, sheet-metal rules, plastic rules, custom) so the top table stays narrow. Right-clicking a theme-table column marks it as a **custom aspect**, whose value is chosen at the point of use instead of being fixed in each row. [vendor] — [Fusion Help: Configurations overview](https://help.autodesk.com/cloudhelp/ENU/Fusion-Configurations/files/CFG-OVERVIEW.htm); [Fusion Help: Configure sheet metal rules](https://help.autodesk.com/cloudhelp/ENU/Fusion-Configurations/files/CFG-SHEET-METAL-RULE.htm)
- **Configuration Rules** "limit or drive configured aspect values based on logical conditions". [vendor] — [Fusion Help: Configurations overview](https://help.autodesk.com/cloudhelp/ENU/Fusion-Configurations/files/CFG-OVERVIEW.htm)
- When configurations are added, new rows copy the *active* configuration. [vendor] — [Fusion Help: Add, rename, duplicate, delete](https://help.autodesk.com/cloudhelp/ENU/Fusion-Configurations/files/CFG-ADD-CONFIGURATIONS.htm)
- **Configuration Mode** highlights configurable features in the Timeline and configurable objects in the Browser so they can be added to the table. Editing an unconfigured aspect affects every configuration; editing a configured aspect affects only the active one. [vendor] — [Fusion Help: Configurations overview](https://help.autodesk.com/cloudhelp/ENU/Fusion-Configurations/files/CFG-OVERVIEW.htm); [Fusion Help: Activate a Configuration](https://help.autodesk.com/cloudhelp/ENU/Fusion-Configurations/files/CFG-ACTIVATE-CONFIGURATION.htm)
- Autodesk's own best practices are to "activate configurations often to validate changes" and, if suppression is configured, to add every suppression state to the table. [vendor] — [Fusion Help: Configurations overview](https://help.autodesk.com/cloudhelp/ENU/Fusion-Configurations/files/CFG-OVERVIEW.htm)
- The API exposes a ConfigurationTable object whose rows are configurations, with a "Top" table and theme tables. [vendor] — [Fusion API: ConfigurationTable](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/fusion_ConfigurationTable.htm); [Fusion API: Configurations user manual](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/Configurations_UM.htm)

**Creo (family tables)**
- A **generic** model owns the family table, and each **instance** is a row. **Verifying** an instance regenerates it. Saving the generic after verification adds the successfully regenerated instances to the instance index. When an instance is opened, Creo uses its **accelerator** file if one exists and regenerates the instance otherwise. [vendor] — [PTC Creo 9 Help: About Instance Operations](https://support.ptc.com/help/creo/creo_pma/r9.0/usascii/fundamentals/fundamentals/About_Instance_Operations.html)
- The ModelCHECK FAMILY_INFO check reports each instance's verification state: generic changed since the last verify, instance modified since the last verify, or never verified. This is a built-in staleness indicator. [vendor] — [PTC Creo 7 Help: FAMILY_INFO](https://support.ptc.com/help/creo/creo_pma/r7.0/usascii/model_analysis/modelcheck/checks/family_info.html)

**NX (part families)**
- A template part plus a family table, built in a spreadsheet, generates the family members. Members are **read-only** files that can only be changed through the template. Newer NX releases embed a spreadsheet in the Part Families dialog, which one user calls "way faster than NX+Excel". [user] — [Eng-Tips: NX2306 family parts issues](https://www.eng-tips.com/threads/nx2306-family-parts-_issues.520695); [Eng-Tips: part family extraction](https://eng-tips.com/threads/part-family-extraction.274545) [historical]
- Siemens support articles document Excel-coupling failures, such as an "Object library not registered" error on the part family spreadsheet and missing add-in options. [vendor] — [Siemens KB PL8668524](https://support.sw.siemens.com/en-US/okba/PL8668524/Object-library-not-registerederror-on-part-family-spreadsheet/index.html); [Siemens KB PL8569364](https://support.sw.siemens.com/en-US/okba/PL8569364/Part-Family-Spreadsheet-Add-in-is-Missing-Options/index.html)

**FreeCAD**
- FreeCAD 1.0 (released November 2024) added **VarSet**, a container of properties that expressions can use as variables. It sits in the Property View next to the design and can be scripted. In 1.0 and below, the VarSet command can't set the list of allowed values for an enumeration property. [vendor wiki/blog] — [FreeCAD wiki: Std VarSet](https://wiki.freecad.org/Std_VarSet/en); [FreeCAD 1.0 release blog](https://blog.freecad.org/2024/11/19/freecad-version-1-0-released/); [Libre Arts: FreeCAD 1.0](https://librearts.org/2024/11/freecad-1-0/)
- The older route uses a spreadsheet **Configuration Table**: right-click a cell and choose "Configuration table…" to create an enumeration that switches rows. It is used together with **Variant Links** (Link objects that hold their own copy of the properties, so one source can appear as several variants, such as M10 and M12 nuts). [vendor wiki] — [FreeCAD wiki: Configuration Tables (mirror)](https://reqrefusion.github.io/FreeCAD-Documentation-html/wiki/Configuration_Tables.html); [FreeCAD wiki: Variant Link](https://wiki.freecad.org/Variant_link)

### Inferences
- Wren's PLAN model is closest to Fusion's flat table and SolidWorks' table: named configurations over a default, parameters by configurations, with suppression, material and custom properties. Onshape's typed inputs (checkbox, bounded variable) are a different axis that can be layered on later. A Wren configuration could be stored as "default + sparse overrides keyed by parameter id", which is the same shape as SolidWorks' derived "override vs linked" model and Fusion's "configured vs non-configured aspect".
- Fusion's theme tables are an answer to table-width blow-up. Wren can get the same result with column groups that collapse (Parameters / Suppression / Material / Properties) instead of separate tables.
- Every mature tool eventually added a way to *find* a configuration by its parameters instead of by name: SolidWorks Configuration Publisher, Onshape's Insert dialog with inputs, and Fusion's custom aspects. Names alone don't scale.

### Gaps
- I found no vendor page that describes Fusion "rule rows" specifically. Only "Configuration Rules" is documented in the overview, and I could not confirm the syntax or the row model. I could not fetch the Fusion FAQ blog post (HTTP 403).
- I found no FreeCAD **1.1**-specific changes to VarSets (for example, enumeration support or VarSet-based configuration switching). Whether 1.1 lifted the "allowed values" limitation is unconfirmed.
- I did not fetch the NX part-family documentation from Siemens itself; the NX findings come from forums and support KBs.
- I could not find Onshape's exact semantics for editing a configured value while a non-default configuration is active. The help page I fetched doesn't cover it.

## 2. Complaints and failure modes

### Takeaway
The dominant complaint is **scope ambiguity**: an edit lands on the wrong configuration, or the scope silently flips from "this" to "all". After that come **performance and file bloat**, which grow linearly with the number of configurations; **Excel coupling** (hangs, failure to open, bloat); **stale variants** (Creo's verify status, SolidWorks' rebuild marks); and **suppression traps**, where features or mates are auto-suppressed in other configurations or reference geometry that is suppressed in this one. Merge conflicts in configured Onshape Part Studios show up mostly as general branch and merge friction, not as configuration-specific conflicts.

### Inferences
- "This vs all" needs to be visible *at the point of edit* and *after the fact* (for example, a cell badge or override marker), not buried in a flyout. SolidWorks' failure is that the scope is a sticky setting the user can't see.
- Parent/child (derived) configurations multiply ambiguity; "this" quietly includes descendants. Wren should leave derived configurations out of M3.7, or make inheritance explicit in the table.
- Rebuild cost scales with the number of configurations. Lazy regen with cached, invalidated results per configuration (Creo's verify plus accelerator, done automatically) is the pattern. Wren should show a "not yet rebuilt / failed / OK" status for each configuration instead of forcing every configuration to rebuild on save.
- A table-level structural merge (per configuration and parameter cell, as PLAN M2.5/M3.7 specifies) would be a real differentiator. No tool in the evidence merges configuration tables at cell granularity.

### Gaps
- I found no explicit, sourced Onshape *configuration-table* merge-conflict report. The merge complaints are about Part Studios in general.
- I found no Reddit (r/onshape, r/Fusion360, r/FreeCAD) threads specifically on configuration complaints; search did not surface them.
- I found no quantitative benchmark of rebuild time against configuration count.
- I found no Fusion user complaints. Configurations are relatively new (2023) and paywalled, so the volume may be low.

## 3. Praised workflows

### Takeaway
Users and vendors praise: configuring a value **in place** by clicking or right-clicking the field in the feature dialog (Onshape's configure mode; SolidWorks' dimension Configurations button); **typed, bounded inputs** with defaults (Onshape variables); a **single grid** of configurations against parameters with spreadsheet paste; **visual marking of overrides** (SolidWorks' yellow in Modify Configurations; Onshape's yellow and blue outlines; Fusion's highlighted timeline items); and **choosing a configuration by parameters at insert time** with a preview.

### Cited Findings
- [vendor] Onshape configure mode: hover highlights every configurable field in yellow, a click adds a column, a parameter already configured is outlined and blocked from double use, and double-clicking a cell jumps back to the feature dialog with the parameter highlighted. — [Onshape Help: Part Studio and Assembly configurations](https://cad.onshape.com/help/Content/PartStudio/part_studio_and_assembly_configurations.htm)
- [vendor] Onshape Insert dialog: the user sets inputs directly, can choose "Set to last viewed configuration" or "Reset to default", clicks **Generate** to refresh the preview, then inserts. The user can then change the configuration of an instance, or of every instance sharing the same part and configuration, in bulk. — same page
- [vendor] Onshape tables accept spreadsheet paste (rows are created automatically), and inputs can be copied and pasted across documents. — [Onshape Help: Configurations](https://cad.onshape.com/help/Content/configurations.htm)
- [user] "Configurations are much better implemented in Onshape", from a comparison commenter who also notes that some variable-linking features lack autocomplete. — [Onshape forum comment 125960](https://forum.onshape.com/discussion/comment/125960)
- [user] SolidWorks users credit configurations as a main reason for choosing the product. — [Onshape forum comment 27539](https://forum.onshape.com/discussion/comment/27539); [Onshape forum comment 27540](https://forum.onshape.com/discussion/comment/27540)

### Inferences
- Wren can combine two praised pieces. One is SolidWorks/Onshape-style *in-place configure*: an inline "∗ this config / all" toggle next to an expression field. The other is a Fusion-style *grid*: the configuration table with spreadsheet paste. Both can be done without modals, which fits the Golden rules.
- A "rebuild all configurations" check that reports per-configuration status (OK, failed, needs attention) is cheap to build in a worker-based kernel. It closes the Creo-style staleness problem without blocking the UI.

### Gaps

- I could not find a sourced Reddit or Eng-Tips post praising SolidWorks' "Configure Feature" or "Configure Dimension" right-click menu by name (as opposed to the help pages).

## 4. Interaction with drawings, BOMs and exports

### Takeaway
Every major tool lets a drawing view reference a specific configuration. The friction is that **the BOM and other annotations don't always follow the view**, and users often fall back to one drawing per configuration. **Tabulated drawings** (one drawing with a table of per-configuration values, and dimensions replaced by aspect names) exist natively in Fusion and through design tables in SolidWorks. **BOM part-number policy** per configuration decides whether configurations group or split in a BOM.

### Cited Findings
- [vendor/user] In Onshape, right-clicking a view lets the user change its configuration at any time, and projected views follow their parent. Running *Change configuration* from the Sheets panel's "sort by reference" changes every view of that reference. — [Onshape Help: View context menu](https://cad.onshape.com/help/Content/Drawing/view_context_menu.htm); [Onshape forum 19722: assembly configurations in drawing views](https://forum.onshape.com/discussion/19722/assembly-configurations-in-drawings-views)
- [user] In Onshape, the drawing BOM may not reference the same configuration as the views and has to be changed separately with right-click *Change Configuration*. — [Onshape forum 22792: drawing BOM and view linked to different assembly configurations](https://forum.onshape.com/discussion/22792/drawing-bom-and-view-linked-to-different-assembly-configurations)
- [vendor/user] The common Onshape workaround is one drawing per configuration: copy the drawing tab, then change the reference configuration. — [Onshape Tech Tip: create a drawing using configurations](https://www.onshape.com/ja/resource-center/tech-tips/how-to-create-an-onshape-drawing-using-configurations); [Onshape forum 12069: drawing automation for configured parts](https://forum.onshape.com/discussion/12069/drawing-automation-for-configured-parts-assemblies)
- [vendor] In Fusion, the user can create one drawing covering all configurations or one per configuration. — [Fusion Help: Configurations overview](https://help.autodesk.com/cloudhelp/ENU/Fusion-Configurations/files/CFG-OVERVIEW.htm)
- [vendor] Fusion tabulated drawing: Tables > Configuration Table places a table that fills automatically, with the user choosing which configured aspects become columns and in what order. A dimension can be right-clicked and replaced with a configured aspect's name ("Replace with Configured Aspect"), so one view stands for many sizes. — [Fusion Help: Create a tabulated drawing](https://help.autodesk.com/cloudhelp/ENU/Fusion-Drawing/files/DWG-CREATE-TABULATED-DWG.htm); [Fusion Help: Edit Configuration Table (Drawing)](https://help.autodesk.com/cloudhelp/ENU/Fusion-Drawing/files/DWG-REF-CONFIG-TABLE-DIALOG.htm)
- [user] A Fusion forum thread asks about displaying the configuration table on drawings, so tabulated output is something users want. — [Autodesk forum: Fusion Configuration display table](https://forums.autodesk.com/t5/fusion-design-validate-document/fusion-configuration-display-table/m-p/13629599)
- [vendor] In a SolidWorks BOM with multiple configurations, separately listed configurations can show a user-specified name, the configuration name or the document name, but grouped ones show only user-specified names. — [SW Help 2020: BOM multiple configurations](https://help.solidworks.com/2020/English/solidworks/sldworks/c_Bill_of_Materials_Multiple_Configurations.htm); [SW Help 2020: BOM Part Number column](https://help.solidworks.com/2020/English/SolidWorks/sldworks/t_Bill_of_Materials_-_Part_Number_Column.htm)
- [vendor] Fusion configurations also flow into Generative Design studies and Manufacturing setups. — [Fusion blog: September 2023 update](https://autodesk.com/products/fusion-360/blog/september-2023-product-update-whats-new)
- [vendor] Uploading through SolidWorks Configuration Publisher to 3D ContentCentral "generates all possible part numbers", which are searchable. This is effectively a per-configuration export of the whole family. — [SW Help 2020: Configuration Publisher](https://help.solidworks.com/2020/English/solidworks/sldworks/c_configuration_publisher_top.htm)

### Inferences
- In Wren M4, a drawing should have a *drawing-level default configuration* that views and BOMs inherit, with a per-view override. This avoids the Onshape trap where the BOM silently points at a different configuration from the view. Any view or BOM that disagrees with the drawing default should be flagged visibly.
- Tabulated drawings (a configuration table plus "dimension shows parameter name") are a natural fit, because Wren configurations are already a parameters-by-configurations table.
- Per-configuration export with "all, one file each" (PLAN M3.7) should name files from the configuration's part-number property when one is set, falling back to the configuration name.

### Gaps
- I found no authoritative Onshape doc on a native tabulated or configuration-table drawing annotation.
- I did not research SolidWorks' per-view "Use named configuration" in the drawing view PropertyManager, or how SolidWorks design tables appear on drawings. This is well known but not cited here.
- I did not find per-configuration *export* features (batch STEP for every configuration) documented in any vendor help page; SolidWorks users usually rely on macros or Task Scheduler (uncited).

## 5. Recommended defaults for a new tool (minimum lovable set, traps, naming)

### Takeaway
Ship a sparse-override model (default plus per-configuration overrides keyed by parameter or feature id) with an inline grid, an always-visible active-configuration indicator, and explicit edit scope at the point of edit with a visible override marker. Leave out external spreadsheets, derived configurations, rules and typed inputs for now. Make "rebuild all configurations" a background check with per-configuration status. Use generic names that avoid vendor terms.

### Cited Findings (evidence behind each recommendation)
- **The scope must be explicit and visible.** A hidden sticky scope flipping to "all" caused silent edits across every configuration ([SW forum 243322](https://forum.solidworks.com/thread/243322)). Fusion's rule is clean: an unconfigured aspect edits all configurations and a configured aspect edits only the active one ([Fusion Help overview](https://help.autodesk.com/cloudhelp/ENU/Fusion-Configurations/files/CFG-OVERVIEW.htm)).
- **Show overrides.** SolidWorks marks overrides in yellow ([SW Modify Configurations](https://help.solidworks.com/2020/English/SolidWorks/sldworks/r_modify_configurations_dialog.htm)), and Onshape outlines configured fields ([Onshape Help](https://cad.onshape.com/help/Content/PartStudio/part_studio_and_assembly_configurations.htm)).
- **Mark the configuration mode clearly.** Onshape's yellow banner ([Onshape Help](https://cad.onshape.com/help/Content/PartStudio/part_studio_and_assembly_configurations.htm)) and Fusion's Configuration Mode highlighting ([Fusion Help overview](https://help.autodesk.com/cloudhelp/ENU/Fusion-Configurations/files/CFG-OVERVIEW.htm)) both do this.
- **Use an in-app table, not Excel.** Evidence: Excel hangs, bloat and add-in errors ([3DSwym freeze](https://3dswym.3dexperience.3ds.com/post/solidworks-user-forum/soliworks-freeze-after-design-table-update_6GALy5iARf6lw-FgsilUkA); [Visiativ swelling](https://forum.mycad.visiativ.com/t/fichiers-excell-qui-enflent/97922); [Siemens KB](https://support.sw.siemens.com/en-US/okba/PL8668524/Object-library-not-registerederror-on-part-family-spreadsheet/index.html)) and the "way faster than NX+Excel" comment ([Eng-Tips](https://www.eng-tips.com/threads/nx2306-family-parts-_issues.520695)). Keep spreadsheet paste, which Onshape supports ([Onshape Help](https://cad.onshape.com/help/Content/configurations.htm)).
- **Don't rebuild every configuration on save.** SolidWorks file size and rebuild time grow with each activated configuration ([SW Help 2019](https://help.solidworks.com/2019/English/SolidWorks/sldworks/c_Managing_Configuration_Data_Help.htm)). Do track staleness the way Creo does ([PTC FAMILY_INFO](https://support.ptc.com/help/creo/creo_pma/r7.0/usascii/model_analysis/modelcheck/checks/family_info.html)).
- **Don't auto-suppress new features in other configurations by default.** CATI reports the vanishing-mates trap ([CATI](https://www.cati.com/?p=119967)). If suppression is configured, show it for every configuration ([Fusion Help overview](https://help.autodesk.com/cloudhelp/ENU/Fusion-Configurations/files/CFG-OVERVIEW.htm)).
- **Downstream references to suppressed geometry must surface as "needs attention" per configuration**, not as a silent break. Evidence: [Onshape forum 29547](https://forum.onshape.com/discussion/29547/unexpected-behavior-advanced-configuration-workflows-exercise-configuring-multi-part-part-studios).
- **Part numbers per configuration change BOM grouping.** Evidence: [SW BOM multiple configurations](https://help.solidworks.com/2020/English/solidworks/sldworks/c_Bill_of_Materials_Multiple_Configurations.htm).
- **New configurations copy the active configuration in Fusion** ([Fusion Help: add configurations](https://help.autodesk.com/cloudhelp/ENU/Fusion-Configurations/files/CFG-ADD-CONFIGURATIONS.htm)). This is a reasonable default, but it should be visible, as in "New from: Default / Active".
- **Selecting a configuration by parameters becomes necessary when there are many configurations.** Evidence: [SW Configuration Publisher rationale](https://help.solidworks.com/2020/English/solidworks/sldworks/c_configuration_publisher_top.htm).
- **Leave derived or nested configurations for later.** Evidence: SolidWorks' "this" includes children ([SW example](https://help.solidworks.com/2012/English/SolidWorks/Sldworks/Example_of_Derived_Configurations.htm)), and Onshape users find nested configurations "difficult to tell what a change will affect" ([Onshape forum](https://forum.onshape.com/discussion/comment/125960)).

### Inferences: proposed minimum lovable set for M3.7
1. **Data model:** `Configuration { id, name, overrides: Map<paramId, expr>, suppressed: Set<featureId> | tri-state per feature, material?, properties: {partNumber?, description?, ...} }` over an implicit Default. Overrides are sparse, so a cell with no override inherits the default. This maps directly onto structural merge with a conflict per (configuration, key), which matches PLAN M3.7.
2. **Active-configuration indicator:** a persistent pill in the top bar showing the configuration's name, plus a tinted edge or banner whenever the active configuration is not the default. One click switches configuration.
3. **Edit scope at the point of edit:** every inline value field shows a small scope chip, "All" or "This config". Editing an overridden value edits the override, and editing a value that isn't overridden edits the default (Fusion's rule). Promoting an edit to an override is an explicit chip click or a modifier key, never a sticky hidden mode. A brief undoable toast can confirm "Changed in all 5 configurations".
4. **Override markers:** in the Params tab and the feature tree, a dot or colour marks values or features that differ from the default, with "Reset to default" on the marker.
5. **Configuration table:** parameters (rows) by configurations (columns), or the transpose, with inline expressions and units, collapsible column groups (Parameters / Suppression / Material / Properties, like Fusion's theme tables), copy and paste from spreadsheets, and diff highlighting against the default.
6. **Suppression:** "Suppress in this configuration only" / "Suppress in all" in the feature context menu. A new feature is *not* auto-suppressed in other configurations.
7. **Rebuild-all check:** a background worker regenerates each configuration on demand or on idle and shows OK, failed or needs-attention per configuration, with failures linking to the broken feature. Results are cached and invalidated per configuration.
8. **Preview strip:** thumbnails of every configuration, generated in the worker. This is low cost, and no competitor in the evidence prominently offers it.
9. **Downstream:** drawings have a drawing-level configuration with a per-view override, and the BOM follows the drawing unless explicitly overridden, with mismatches flagged. Assemblies (M6) store a configuration id per instance and support bulk change by selecting "same part + same configuration", like Onshape. Exports offer "all configurations, one file each", named from the part number when one is set.

**Traps to avoid:** an external spreadsheet as the source of truth; a sticky, invisible "this / all" mode; auto-suppressing new features in other configurations; derived configurations in v1; rebuilding every configuration on every save; BOM or drawing references that drift from the view's configuration; configuration identity by name rather than id (renames would break merges and references).

**Trademark and term notes (for generic naming):**
- Vendor-specific UI names to avoid in Wren: *ConfigurationManager*, *PropertyManager*, *Configuration Publisher*, *Design Table*, *SpeedPak*, *3D ContentCentral* (SolidWorks / Dassault Systèmes); *Part Studio*, *Variable Studio*, *FeatureScript* (Onshape / PTC); *Family Table*, *Instance Accelerator* (Creo / PTC); *Part Families* (NX / Siemens); *Theme Table*, *Configured Design* (Fusion / Autodesk). Product names: SOLIDWORKS, 3DEXPERIENCE, Onshape, Creo, NX, Fusion and FreeCAD. These are the terms as they appear in the vendor help pages cited above. Whether each phrase is a registered trademark is **not verified** (see Gaps).
- Generic terms that are safe to use: "configuration", "variant", "configuration table" (Fusion and FreeCAD both use this ordinary phrase), "parameter table", "override", "default", "suppress in this configuration".

### Gaps
- I did not verify which of the phrases above are registered trademarks, as opposed to unregistered product feature names. Checking USPTO or EUIPO records was out of scope. "Design table" and "configuration table" read as ordinary English, but SolidWorks uses "Design Table" as a capitalised feature name. The conservative choice is "configuration table" or "parameter table".
- I found no usability study (quantitative) comparing in-place configure with table-first workflows. The recommendations above rest on vendor documentation and anecdote.
- The assembly-configuration specifics for M6 (mate values per configuration, instance suppression) were only touched on through Onshape: mates, instances and patterns can be configured, but mate connectors can't ([Onshape Help](https://cad.onshape.com/help/Content/PartStudio/part_studio_and_assembly_configurations.htm); [Onshape Help: Assembly configurations](https://cad.onshape.com/help/Content/assembly_configurations.htm)). They need deeper research before M6.
